# Provider-run chats drive Claude cloud sessions from a host device

Zeron runs a provider-run chat by having one of the user's own devices act as its host: the host's engine talks to Anthropic's private Claude Code session API (the endpoints claude.ai/code uses) with the user's own Claude login, streams the session's events into the chat, and sends the chat's messages, interrupts and prompt answers back. The provider cloud session is the record of the conversation; the Zeron chat mirrors it and stays a normal chat in the sidebar, while the session keeps working at Anthropic when every device is off. The feature is personal and experimental, lives only on a nightly branch, and starts with Claude.

We chose this over the documented paths because none of them can carry a live chat: `claude -p --cloud` only queues a message, `--teleport` copies a session away, Remote Control runs the agent locally, the CLI's headless cloud bridge is gated off for the account, and the Managed Agents API bills an API key and isn't a claude.ai/code session. Zeron's own relay and Zeron Cloud machines can't host these chats because they run the Zeron team's builds, which a personal branch can't change; if the relay is ever self-hosted, it could host provider-run chats with no device involved. Exposing Zeron's tools to the cloud session is left out of the first phase. The accepted cost is an undocumented API that can change without notice, and terms-of-service risk carried by the user's Claude account and Team. To keep that risk as low as possible, Zeron identifies itself honestly instead of impersonating the CLI, leaves every login and token refresh to the official CLI, and calls only the session endpoints claude.ai itself uses. The design is in `docs/design/provider-run-chats.md`.
